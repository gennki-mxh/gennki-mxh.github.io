关于我

我是GennKi，一名从纺织工程转向编程的开发者。目前正专注于前端开发与 Python 后端方向，寻找第一份技术工作。

毕业后，我经历了一段探索期。我没有急于盲目投递简历，而是选择用将近一年时间，从零系统学习底层原理，并独立从零搭建了本站。在这个过程中，我发现自己最擅长的是“弄清楚一个东西到底是怎么跑起来的”——从 Python 的对象复用与编译机制，到 CSS 的层叠与 DOM 渲染。这种“不满足于表面调用，死磕底层逻辑”的习惯，成了我学习技术的主要方式。

🛠️ 技术栈与工具

  • 前端基础：HTML5 / CSS3 / SCSS / 多端响应式适配 / 浏览器开发者工具深度调试

  • 后端探索：Python / Flask / 基础 RESTful API 设计 / MySQL 基础增删改查

  • 工程化与部署：Git 版本控制 / GitHub / GitHub Actions（CI/CD 自动化部署）

  • AI 与效率：熟练使用 DeepSeek、Kimi 等 AI 辅助工具进行代码生成、报错分析与逻辑验证

  • 其他开发工具：VSCode / PyCharm / Navicat

🚀 核心项目

个人时间管理系统后端 API (2026.10 - 至今)

简介：一个为量化个人时间分配而开发的 RESTful API 服务。

技术栈：Python / Flask / MySQL / PyMySQL / Git

项目亮点：

  • 独立设计并实现了完整的 CRUD（增删查改）接口闭环。

  • 具备防御性编程思维，实现了接口层的参数校验（拦截非法数据）。

  • 解决了前后端分离架构下的 CORS 跨域限制。

  • 能从零到一独立完成系统的开发、联调与部署。

  • 项目链接：Time Tracker Backend

说明：

  • 这个时间管理系统，我最初是用 CSV 文件存数据，后来为了实战后端，我重构了架构，用 Flask + MySQL 重写了接口。

  • 在开发过程中，我遇到了令人抓狂的 CORS 跨域问题。我通过查阅文档，并在浏览器的 Network 面板里抓包分析，最终引入了 flask-cors 解决。

  • 为了防止前端传入负数（比如睡了 -1 个小时），我在接口层加入了防御性校验，返回标准的 400 状态码。

个人独立博客系统（2026.7 - 至今）

技术栈：HTML/ SCSS / Hugo / Git / GitHub Actions

页面深度还原与美化：通过阅读源码和排查开发者工具，独立完成博客主题的深度定制。熟练运用 Flex/Grid 布局及 CSS 变量，实现了亮暗主题切换、动态背景适配及各类交互效果。

复杂问题排查：独立定位并修复了多项系统异常（如动态背景半屏断裂、CSS 优先级冲突等），具备清晰的逻辑推理与 Debug 能力。

工程化与自动化部署：采用源码与静态页面分仓管理策略，配置 GitHub Actions 编写工作流，实现从本地 Markdown 提交到线上发布的 CI/CD 全自动构建，深刻理解前后端协同与工程化流程。

技术沉淀：将开发全过程记录在博客的“足迹”页面，并撰写了《看答案能懂，自己写就懵？我从零推导了 trim() 函数》等深度技术文章，具备将复杂逻辑转化为高质量文档的能力。

说明：

  • 我希望能有个对外展示我的学习过程和成果的窗口，觉得有个博客最合适，于是选择使用 Hugo 来搭建。因为有现成的视频教程，让我熟悉配置文件，但版本不同，又让我踩了很多坑。不过这些坑，最后都变成了经验，成了博客的地板砖。

  • 博客开发历时大约 80 天，每天开发时间大约 2-3 小时，最长的开发时间高达 5 个小时。

  • 最开始遇到诸多困难和未知 bug，但还好没放弃，通过 DeepSeek 逐步排查并最终解决了问题。完事开头难，过了第一关，剩下的路就相对好走得多了。

比起快速套用现成方案，我更习惯先定位问题、设计小实验验证假设，再落地修改。我深知自己在商业项目与主流框架上仍需积累，但我相信扎实的底层基础、熟练的 AI 辅助能力以及极强的自主学习力，能让我快速胜任并融入团队。
